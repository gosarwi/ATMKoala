# ATMKoala v0.5 — ATMUEFI native boot release

**Платформа:** freestanding x86-64, C + ASM, без libc.  
**Новая возможность:** собственный UEFI x86-64 boot path **ATMUEFI**, проверенный в OVMF/QEMU.

> ATMUEFI не заменяет рабочий BIOS ATMBOOT и GRUB ISO. Релиз поставляет три независимых пути запуска одного kernel image: UEFI ESP, raw BIOS image и GRUB ISO fallback.

## Что добавлено

| Компонент | Реализация |
|---|---|
| **ATMUEFI application** | Native PE32+ `EFI application` в `\\EFI\\BOOT\\BOOTX64.EFI`; корректный UEFI subsystem (`10`). |
| **EFI System Partition** | 64 MiB GPT image с partition type `EF00`, FAT32 label `ATMUEFI` и стандартным removable-media boot path. |
| **Kernel payload** | `\\EFI\\ATMKOALA\\KERNEL.BIN`, generated by `objcopy -O binary`; UEFI loader читает его через Simple File System. |
| **Graphics handoff** | Loader запрашивает GOP, формирует compatible framebuffer information block и передаёт его в существующее ядро. |
| **ExitBootServices** | После final memory map loader прекращает Boot Services ownership и передаёт управление нативному kernel entry. |
| **Direct 64-bit entry** | Ядро получило `uefi_start`: сохраняет long mode, перестраивает собственные identity page tables, перезагружает kernel GDT CS selector и использует общий initialization path. |
| **Memory layout** | Kernel base перенесён на `64 MiB`; heap — на `128 MiB`, что убирает конфликт с allocations UEFI firmware в low memory. |
| **ABI protection** | GNU-EFI loader собран с MS x64 ABI для direct UEFI protocol/Boot Services calls. |
| **Build guard** | `make atmuefi` asserts the checked physical `uefi_start` offset before constructing ESP. |

## Артефакты и назначение

| Файл | Назначение | Способ запуска |
|---|---|---|
| `ATMKoala-v0.5-ATMUEFI-GPT-ESP.img` | Native UEFI GPT/ESP image. | UEFI firmware / OVMF; QEMU USB-removable path. |
| `ATMKoala-v0.5-ATMBOOT-BIOS.raw` | Independent legacy BIOS raw disk image. | BIOS/QEMU IDE, без GRUB. |
| `ATMKoala-v0.5-ATMUEFI-Exp.iso` | GRUB ISO fallback. | QEMU CD-ROM или GRUB-compatible boot environment. |
| `ATMKoala-v0.5-ATMUEFI-Exp-src.tar.gz` | Reproducible source archive. | `make atmuefi`, `make atmboot`, `make iso`. |

## Сборка

```bash
make all
make atmuefi     # UEFI GPT ESP image
make atmboot     # legacy BIOS raw image
make iso         # GRUB fallback ISO
```

## OVMF/QEMU: нативная UEFI проверка

Следующий пример подключает ESP как USB-removable device; это гарантирует, что OVMF использует стандартный `\\EFI\\BOOT\\BOOTX64.EFI` fallback path.

```bash
cp /usr/share/OVMF/OVMF_VARS_4M.fd /tmp/ATMKOALA_VARS.fd
qemu-system-x86_64 \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE_4M.fd \
  -drive if=pflash,format=raw,file=/tmp/ATMKOALA_VARS.fd \
  -drive if=none,id=esp,file=ATMKoala-v0.5-ATMUEFI-GPT-ESP.img,format=raw \
  -device qemu-xhci,id=xhci \
  -device usb-storage,drive=esp \
  -m 256M -vga std -no-reboot
```

## Проверка

| Сценарий | Результат |
|---|---|
| OVMF → USB GPT ESP → ATMUEFI → GOP → kernel | **Пройден.** Loader reports GOP `1280x800`; kernel reports VBE OK; Exp terminal is interactive. |
| BIOS → ATMBOOT stage 0/2 → ATA PIO → kernel | **Пройден.** Raw image reaches Exp with VBE OK. |
| GRUB ISO → Multiboot2 → kernel | **Пройден.** Fallback ISO reaches Exp with VBE OK. |

## Текущие границы

ATMUEFI — полноценный native UEFI boot path для **x86-64 UEFI with GOP**. Однако он пока не является универсальным production boot manager. Secure Boot signing, UEFI runtime services after kernel takeover, generic ELF relocation, multi-architecture boot, direct NVMe handling in the pre-kernel loader и LBA-independent kernel filesystem loader намеренно остаются следующими этапами. BIOS ATMBOOT и GRUB ISO сохраняются как проверенные совместимые fallback paths.
