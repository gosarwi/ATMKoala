# ATMKoala POSIX Compatibility Status

**Status:** Local implementation record for ATMKoala v0.9, **native ABI v1.22**, **native syscall ABI v22**, and the bounded **Linux x86-64 ABI L3** adapter. The practical source-profile estimate is now **approximately 50%** under the project’s documented, weighted profile method. This is **not** POSIX certification, complete Linux ABI compatibility, BusyBox/Toybox compatibility, musl readiness, or a claim that arbitrary binaries execute.

> A facility is counted only when it has defined bounded semantics, checked CPL3 memory handling where applicable, an implementation in the freestanding runtime or kernel, and a real CPL3/QEMU regression. Headers, stubs, and unconditional-success paths contribute no profile coverage.

## Scope of the estimate

The estimate covers the practical static-application profile that is relevant to ATMKoala today: files and namespace operations, descriptor lifecycle, directories, bounded process lifecycle, startup/runtime, time queries and sleep, memory basics, and a small Linux-oriented runtime adapter. It deliberately assigns little or no weight to still-absent `fork`, signals, threads, dynamic linking, terminal control, full sockets, and advanced asynchronous I/O.

## ABI versions and Linux adapter

The native public header reports **ABI major 1, minor 22**. `ATM_SYS_ABI_INFO` reports **syscall ABI v22**. The static libc smoke verifies that the public ABI probe returns v22, preventing a stale runtime/kernel version report.

The Linux entry remains a separate x86-64 `syscall` path. It is an adaptation layer for carefully selected static-runtime operations, not an alternative kernel personality.

| Linux level | Verified calls | Boundary |
|---|---|---|
| L0 | `read`, `write`, `open`, `close`, `getpid`, `kill`, `fchdir`, `fchmod`, `fchown`, `getrusage(RUSAGE_SELF)`, `times`, `getrlimit`, `faccessat`, `mkdirat`, `unlinkat`, `renameat`, `linkat`, `symlinkat`, `readlinkat`, `getpgid`, `setpgid`, `getsid`, `setsid`, `getuid`, `getgid`, `geteuid`, `getegid`, `getresuid`, `getresgid`, `chown`, bounded `execve`, `dup3`, `pipe2`, `preadv`, `pwritev`, `exit`, `exit_group` | Direct numeric compatibility only for the verified subset. Linux `dup3` accepts only `O_CLOEXEC`; Linux `pipe2` accepts only `O_CLOEXEC|O_NONBLOCK`, which are translated to native flag values. Linux `preadv`/`pwritev` reconstruct the split `pos_l`/`pos_h` offset and retain native 16-vector/seekable-FD limits. `fchdir` is task-owned directory-descriptor only. `fchmod`/`fchown` operate only on owned VFS-backed descriptors and retain VFS authorization/backing-store limits. `getrusage` accepts only `RUSAGE_SELF` and exposes partial tick/residency/context-switch accounting. `times` returns uptime and self task ticks only, with system/child fields zero. `getrlimit` supports only read-only fixed `RLIMIT_STACK`, `RLIMIT_NOFILE` and `RLIMIT_AS`. Linux legacy three-argument `faccessat` forces native `flags=0`; namespace `*at` operations accept only `AT_FDCWD`; `unlinkat` permits `AT_REMOVEDIR` and `linkat` flags must be zero. `kill` retains native signal-0 and direct-child-only boundaries. Group/session calls retain native self/direct-child and no-controlling-terminal boundaries. Identity stays single-credential, `chown` remains VFS-permission-bound, and Linux `execve` shares native bounded vector limits. |
| L1 | `brk`, anonymous private `mmap`, `mprotect`, `munmap` | 128 MiB bounded user window; no shared/file-backed mapping. |
| L2 | `arch_prctl` for FS base, `set_tid_address`, `gettid`, `uname` | TLS and identity foundation only; no full thread implementation. |
| L3 | `openat`, `newfstatat`, `getdents64` | `openat` and `newfstatat` accept **only `AT_FDCWD`**. `newfstatat` accepts flags `0` or `AT_SYMLINK_NOFOLLOW`. `getdents64` requires an owned directory fd and a caller buffer of at least 280 bytes. |

Linux L3 translates only the explicitly accepted flags. Unsupported flags and non-`AT_FDCWD` dirfds fail rather than being guessed or silently redirected. `getdents64` uses an fd-backed VFS iterator whose offset advances after each emitted entry.

## Installer UI, timezone and Exp text boundaries

The GUI Disk Install path now draws the same outlined white arrow as Exp, with its visual tip and every hitbox sharing the mouse hotspot. It presents compact disk glyphs in drive selection and visualizes the proposed partition span before the destructive confirmation step. The same primary-button rectangle is used for visual placement and mouse activation. After the exact keyboard token `ERASE` is complete, **Enter** or a click on the enabled **Install** button starts the destructive operation; Enter is evaluated as an activation key before token input and therefore cannot reset the completed token. Its regression is deliberately pure UI/layout/state logic; it does not mount, format, inspect or write a disk. Actual installation remains gated by the existing explicit destructive confirmation and retains the preflight path. After a successful format, mount and account/timezone write, it presents a black **`atmkoala`** completion splash for two PIT-timed seconds before showing Finish; failure paths do not show the success splash. The locale/account step now stages an optional standard local user alongside the root password. Its name must begin with a letter and may then contain letters, digits, `_` or `-`; its password must contain at least four characters. The staged user is never added to the running system while fields are edited. It is created only after the confirmed target is formatted, mounted and the root password is stored, and its password is persisted only as an account hash. Installer-created optional users have the standard `ROLE_USER` role, not administrator privileges.

## Init diagnostics and memory lamps

`kprintf` now retains a bounded in-memory chronological ring in addition to normal console output. `initctl kernel [N]` displays the latest formatted kernel records, while the existing `initctl log [N]` displays init/service/application events; successful GUI windows and static native process launches are recorded as source-tagged init events. The ring is intentionally volatile and does not claim to be a persistent replacement for the CatFS-backed init log.

`initctl memory` and the Exp System Monitor provide green/yellow/red heap-pressure lamps. These lamps use only real allocator counters: green below 75% heap use, yellow at 75–89%, and red at 90% or more. They separately show scheduler-tracked task-resident bytes and task count. Neither view represents this as total physical RAM, per-process RSS, swap state, or an OOM predictor.

The installer timezone selector includes `Asia/Yekaterinburg`, `Asia/Omsk`, `Asia/Novosibirsk`, `Asia/Krasnoyarsk`, `Asia/Irkutsk`, `Asia/Yakutsk`, `Asia/Vladivostok`, `Asia/Magadan`, and `Asia/Kamchatka`. A single shared embedded catalogue backs installer validation, `timezone list`, `timezone set <Zone>`, `timezone now [Zone]`, Calendar and Exp Clock. `timezone list` enumerates every available identifier; `timezone now <Zone>` previews current civil time without changing the saved selection. `date`, Exp Clock and Calendar convert an RTC configured as UTC to selected local civil time. The built-in table remains current-era fixed-offset/DST logic for its listed zones.

`tzif import <source> <IANA-name>` validates one regular source file and copies it exclusively to `/data/uiu/tzif/<IANA-name>` through mounted CatFS; it refuses files larger than 8 KiB, unsafe names and replacement of an existing archive object. `tzif use <IANA-name>` then loads one selected TZif v1/v2/v3 transition/type file, capped at 64 transitions and 16 types, and makes it the conversion source for `date`, Calendar and Exp Clock. `tzif remove <IANA-name>` deletes only that selected CatFS object and clears it from the active conversion state; `tzif status` reports the active archive zone. The reader follows the documented TZif transition/type model [2], but ATMKoala does **not** ship, download, enumerate or automatically update a full IANA archive.

`ntp sync <IPv4-or-hostname>` is a manual, one-request NTPv4-compatible operation over the bounded internal UDP helper. The helper resolves an ARP cache entry or issues one ARP request for an on-link destination or configured UserNet gateway, with a one-second bound; it is still not a user UDP socket ABI or generic packet demultiplexer. NTP validates the reply's leap indicator, version, server/broadcast mode, nonzero stratum and transmit-second range before applying an in-RAM UTC correction; `ntp status` reports that correction. A separate destructive command, `ntp write-rtc WRITE_RTC`, requires exact confirmation and an UTC RTC basis, writes the already reviewed corrected UTC value to CMOS, verifies date/hour/minute readback and clears the volatile correction only on success. There is no retry in the background, authentication, frequency discipline or external NTP QEMU proof. NTP is specified as an Internet clock-synchronisation protocol [3], but this implementation deliberately covers only the bounded manual request/reply subset.

> IANA states that the TZ Database is periodically updated when authorities change boundaries, UTC offsets and DST rules; an ATMKoala update and user-supplied replacement TZif file are required when a loaded region changes its civil-time law.[1]

Exp Calendar reads the same validated RTC/local-time source and probes it once per second while visible. In follow-today mode it redraws only after an actual local-day change, so date/month rollover is not dependent on keyboard or mouse input; manual month navigation remains frozen until `T` returns to today. The Exp launcher also contains a bounded native Flappy Bird window with one fixed pipe pair, keyboard/mouse flap, score and restart. Its mandatory pure Exp selftest covers a pipe-gap safe case, a pipe collision and a no-pipe case; it is not a claim of automated graphical-play testing.

The Exp launcher also contains a bounded native **Tetris** window: fixed 10×20 board, deterministic local piece stream, gravity, rotation, soft/hard drop, collision, line clear, score and restart. Its pure Exp selftest validates a spawn collision boundary and one complete-line removal; it is not an automated graphical gameplay test.

The normal VBE graphical boot path now shows a short black-and-white **ATMKoala** startup splash with `initialising desktop` for approximately 1.2 seconds after fonts initialise and before Exp takes ownership of its first frame. A framed lower monochrome indicator travels across the same interval. It does not run in text mode or installer mode, and it is distinct from both the idle screensaver and successful-installer completion splash. QEMU requires the `[boot] splash-shown` marker to confirm this branch executed; it is not a copied third-party logo, a full animation, a measured subsystem-progress system or firmware boot-logo replacement.

Exp Power offers Halt and Restart buttons only after a second explicit Enter confirmation. Both reuse the established `atminit_shutdown` plus `catfs_sync` sequence; restart then requests keyboard-controller reset while halt stops the CPU. **Sleep is visibly present but deliberately unavailable** because ACPI S3 suspend/resume, wake-up and device reinitialization are not implemented. The Exp idle screensaver begins after five minutes by default; `desktop.screensaver_minutes` may set only 5–10 minutes, invalid values fall back to five. Keyboard input, a button transition, or pointer motion exceeding two physical pixels dismisses it; sub-three-pixel coordinate noise no longer prevents auto-start or immediately hides the saver. Settings → System provides **P. Preview screensaver** for an immediate check. The saver renders a bounded bouncing `ATMKOALA` label with the `desktop idle mode` subtitle. The existing Exp/QEMU pure test validates timeout bounds and this activity threshold; it is not a five-minute wall-clock graphical interaction test. It is a desktop screensaver, not hardware display power management or system sleep.

Exp now exposes a separate read-only **System Information** application. It displays CPUID vendor/brand/features, physical-memory discovery, heap/task-residency accounting, storage/network counters and battery/radio state from existing trusted sources. Its wording preserves critical boundaries: task-resident bytes are not RSS; device detection does not mean a complete native driver; and the page does not probe hardware directly. The new **Events** application reads the bounded chronological init/service ring and the separate formatter `kprintf` ring. `Tab` switches rings and keyboard scrolling moves through retained history. Both rings are volatile in-memory observability aids; neither is a complete audit journal nor a claim of CatFS persistence.

Exp now ships fourteen built-in procedural wallpapers: Paper, Porcelain, Grid, Lines, Azure, Horizon, Orbit, Cobalt, Aurora, Ink, Snow, Checkers, Scanline and Mono Rings. The Appearance page presents all fourteen in a four-column picker; keyboard `1`–`9` selects the first nine and pointer cards select every entry, including the five added monochrome designs. Choice persistence now accepts the multi-digit IDs required by entries 10–14, while external PNG/JPEG/BMP wallpaper application remains a separate decoded-image path. These are generated VBE patterns, not bundled raster artwork, slideshow support or a background compositing service.

Exp windows now have a visible bottom-right drag-resize grip. Mouse resize is disabled for maximized windows and clamped to 220×140 minimum content-safe geometry and the desktop/taskbar bounds; it is not a retained compositor or application-specific reflow engine. The PS/2 pointer path now publishes one coherent cursor snapshot per Exp/installer consumer frame instead of mixing IRQ-mutated `x`, `y` and button fields. It also rejects a completed packet whose sign flags disagree with the two movement-byte sign bits, preventing a malformed or desynchronised tuple from becoming a large cursor jump. QEMU asserts valid and invalid packet-sign combinations through `[mouse] packet-ok`; it does not certify every physical PS/2, touchpad, USB-HID or firmware-controller implementation.

Paint has one bounded per-window undo step, a contiguous-region bucket fill and palette clicks in addition to pixel painting, eraser and clear. `M` marks the current cell, then `L` draws a bounded Bresenham line to the current cursor and `R` draws a bounded outline rectangle; the mark remains visibly outlined and each geometric action consumes the same one undo step. `S` writes the 32×18 logical canvas as a binary RGB **PPM P6** file to collision-safe `/data/uiu/paint/paint-01.ppm` through `paint-99.ppm`, streaming one 96-byte row and removing partial output after a failure. Saving requires mounted CatFS. There is no PNG/JPEG encoder, scaled raster export, undo history beyond one step or cross-session drawing persistence.

Files retains CatFS Trash and New Folder, and now adds a per-window bounded clipboard for regular files only: `C` selects copy, `M` selects move and `P` pastes after navigation into a different folder. Copy is streamed in 512-byte VFS chunks and capped at 256 KiB; paste refuses overwrite and removes a partial target on error. Directories, recursive copy, cross-mount move and arbitrary text rename are intentionally not claimed.

The dedicated Ext2 shell writer remains guarded: clean, non-journaled volumes only; existing non-sparse direct data blocks only; no allocation, truncate, directory update or indirect metadata mutation. `tests_qemu_ext2_write_type.sh` now creates an MBR+Ext2 disk image, runs the guarded `ext2 write` path under QEMU and verifies persisted bytes with `debugfs`; it does not broaden the Ext2 claim.

Exp now includes a separate **Screenshots** application, reachable from the desktop icon and launcher. `S`, Enter, or **Capture** saves the currently presented 24- or 32-bpp VBE framebuffer as a binary **PPM P6 RGB** file. The writer creates `/data/uiu/screenshots/` only through the mounted CatFS VFS, writes one bounded RGB scanline at a time, uses collision-safe `O_EXCL` slots `atmkoala-01.ppm` through `atmkoala-99.ppm`, and removes a partial file after an allocation or write failure. It explicitly reports no save when CatFS is not mounted, when VBE is unavailable/unsupported, or when all slots are occupied. PPM is the sole capture format: there is no PNG/JPEG encoder, thumbnail/gallery, sharing service, text-mode capture, or claim that a full-screen image includes anything outside the VBE framebuffer. The Exp regression now validates the PPM header, deterministic path construction, and synthetic 24-/32-bpp BGR/BGRA-to-RGB scanline conversion inside the existing QEMU `posix test` marker; because the stock test ISO does not mount a writable CatFS target, it does **not** claim an end-to-end persistent capture regression.

Exp Clock now presents the selected local date and time, offset/DST state or explicit RTC error, plus a per-window stopwatch. Its **Timezone Preview** uses Left/Right or pointer controls to browse the same embedded catalogue and `A`/Set active to persist the chosen zone; browsing itself does not mutate the active selection. The preview requires an UTC RTC and explains when the firmware-local basis makes conversion unsafe. The stopwatch has keyboard `S`/Space to start or pause, `R` to reset and equivalent mouse buttons. Its elapsed time comes from monotonic 100 Hz PIT ticks, so it continues independently of CMOS RTC availability, timezone selection or UTC/local basis changes.

`atm-box tail [-n N] <file>` provides a seekable, line-oriented last-0..64 view with a 64 KiB scan and 8 KiB output limit. `atm-box grep <literal> <file>` performs literal matching only, with a 63-byte pattern, 64 KiB scan, 255-byte line buffer and 128-match output cap; neither command implements regex, pipelines or unbounded text buffering. The native POSIX wrapper also exposes VFS-defined `atm_posix_pathconf`/`atm_posix_fpathconf` for name, path and hard-link limits only; this is not a device-specific host filesystem query or a new Linux syscall.

Exp now has bounded UTF-8 rendering helpers. Window titles clip before window controls on codepoint boundaries; localized Settings tabs use codepoint metrics; and localized prose wraps within the content pane. This prevents Russian text from crossing the right edge or being split inside a UTF-8 sequence. It is a UI-layout correction, not a new text-shaping, variable-width-font, or full internationalization engine.

## Package download path

The package shell provides direct `pkg fetch http://host/path/package.atpk` plus repository convenience commands: `pkg repo show`, `pkg repo set http://host/base`, and `pkg get <native-package-name>`. The repository base is persisted in `/uiu/etc/packages.conf`; `pkg get` deterministically resolves the package URL as `<base>/<name>.atpk`. The command requires UserNet to be configured and up, resolves a hostname through the existing bounded DNS path (or accepts dotted IPv4), downloads through the existing TCP client, accepts only HTTP status `200` with one bounded `Content-Length`, and streams the body in at most 512-byte TCP chunks.

Before installation, the response must parse as a native ATPK archive with `ATPK/control` and `ATPK/manifest`; legacy `.tar.zst` is intentionally refused for remote intake. A validated body is written with `O_EXCL` to `/uiu/cache/packages/<name>.atpk.download`, renamed to `/uiu/cache/packages/<name>.atpk`, and only then passed to the existing transactional installer. Existing cache objects are not overwritten implicitly.

> This is a deliberately limited **clear-text HTTP** bootstrap path. It rejects `https://`, redirects, authentication, chunked transfer encoding, proxy configuration, persistent connections, and oversized bodies. There is no TLS authenticity or transport confidentiality claim. Production repository trust requires a future signature and HTTPS/TLS design.

The terminal command `ixpy` is a constrained built-in interpreter. It accepts signed 32-bit integer literals, `+ - * / %`, parentheses, up to eight local identifier assignments and `print("text")`/`print(expression)`. The documented form `ixpy ( print ("hello world") )` is supported. It intentionally rejects imports, files, functions, classes, loops, lists/dictionaries, `eval`, modules, bytecode and CPython extensions; it is a parser convenience, not Python/CPython compatibility. The safe `power`, `events` and `sysinfo` command aliases open their corresponding Exp windows only while Exp is active.

The active boot-development policy is Limine-only: `atmkoala-OS-v0.9-limine.iso` is the sole supported feature-development/release artifact. ATMBOOT and ATMUEFI remain archived legacy paths outside `make atmloader`; see `docs/BOOT_POLICY.md`. The final local artifact is rebuilt and QEMU-tested locally only. No kernel source or ISO publication, repository publication, or GitHub operation is part of this milestone.

## Explicit non-claims and next work

ATMKoala does **not** claim POSIX certification, arbitrary Linux binary execution, musl portability, glibc support, dynamic linking, complete BusyBox/Toybox support, a full socket API, full signal semantics, `pthread`, futexes, `statfs`/`fstatfs`, unbounded/full `execve` vectors, mutable environment APIs, or `fork`.

The highest-value next work is to add a VFS-wide mounted-backend information contract before `statfs`/`fstatfs` are claimed, evolve the bounded environment and argument model only with retained user-pointer validation, design a real signal/futex/thread model, add properly timed readiness waits for supported descriptor classes, and expand Linux runtime calls only with corresponding CPL3/QEMU tests. Any such work must retain the bounded address-space, independent-code, and no-unverified-feature rules recorded here.
